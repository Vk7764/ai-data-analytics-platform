# Deterministic Intelligence, Quality, and Cleaning Plan

This document describes the deterministic, rule-based analytics layer added to the Data Analytics app.

These features are intentionally **not AI-generated**. They use pandas/profiler/cleaning rules and do **not consume AI quota**.

---

## 1. Purpose

The deterministic intelligence layer gives users:

- repeatable data quality reporting
- semantic-layer style metric catalog
- rule-based narrative summary
- safe cleaning recommendations
- preview/apply workflow for cleaning actions
- exportable JSON/Markdown snapshots

This is useful for:

- support debugging
- data onboarding
- cleaning governance
- report fallback when AI summary is unavailable
- building trust by separating AI output from deterministic output

## 2. Backend Endpoints

### Quality Report

```text
GET /dataset/{dataset_id}/quality-report
```

Returns detailed deterministic quality report:

- row count
- column count
- total cells
- missing cells
- completeness percent
- duplicate rows
- duplicate row percent
- primary key candidates
- issue counts
- average unique ratio
- health score
- profile health score
- detected date columns
- freshness
- column-level quality
- truncation flags

Response includes:

```json
{
  "generated_by": "deterministic-quality-engine",
  "ai_generated": false
}
```

---

### Narrative Summary

```text
GET /dataset/{dataset_id}/narrative-summary
```

Returns a rule-based “data story”:

- dataset size

- duplicate rows
- possible keys
- candidate measures

Response includes:

```json

  "ai_generated": false,
  "disclaimer": "This summary is generated by deterministic rules and does not use AI quota."
}
```

---

### Cleaning Plan

```text
GET /dataset/{dataset_id}/cleaning-plan
```

Returns deterministic cleaning recommendations based on detected data quality issues.

Each plan item includes:

- action
- column
- reason
- risk
- preview_supported
- applies_automatically
- preview_request

Risk levels:

- `safe`: usually low-risk normalization/formatting
- `review`: should be previewed before applying

Response includes:

```json
{
  "generated_by": "deterministic-cleaning-plan",
  "ai_generated": false,
  "disclaimer": "This plan is rule-based. Review preview before applying destructive actions."
}
```

Important:

- The cleaning plan does **not** modify data by itself.
- The frontend can preview an action using the existing `/clean/preview` endpoint.
- The frontend can apply an action using the existing `/clean` endpoint after user confirmation.

---

### Combined Intelligence

```text
GET /dataset/{dataset_id}/intelligence
```

Returns all deterministic intelligence in one response:

```json
{
  "dataset_id": "...",
  "data_version": "...",
  "quality": {},
  "catalog": {},
  "narrative": {},
  "cleaning_plan": {},
  "generated_by": "deterministic-intelligence-combined",
  "ai_generated": false
}
```

This endpoint is used by the frontend Dataset Intelligence panel to reduce network calls.

If the combined endpoint fails or misses a section, the frontend falls back to individual endpoints.

## 4. AI vs Deterministic Behavior

### AI-generated features

These may use AI quota:

- AI Insight
- AI Cleaning Advisor
- AI anomaly explanation
- AI root-cause explanation
- AI SQL generation
- AI Python code generation
- AI chat replies

UI labels/disclaimers were added where relevant:

```text
AI-generated
Verify recommendations before applying cleaning actions.
AI output may be cached until the dataset changes.
```

---

### Deterministic features

These do **not** use AI quota:

- Quality Report
- Quality Summary
- Metric Catalog
- Narrative Summary
- Cleaning Plan
- Combined Intelligence
- Deterministic report fallback

UI labels:

```text
0 AI quota
Not AI-generated
Rule-based
```

## 5. Report Integration

The report endpoint supports deterministic fallback:

```text
GET /dataset/{dataset_id}/report
```

Query parameter:

```text
include_deterministic_summary=true
```

Default:

```text
true
```

If AI executive summary is unavailable and deterministic summary is enabled, the report includes:

```text
Deterministic summary (rule-based, not AI-generated):
```

followed by a deterministic quality snapshot when available.

This ensures reports remain useful even when AI output is unavailable.

## 6. Saved Analyses

Saved analysis types now include deterministic intelligence types:

```text
quality_report
metric_catalog
narrative_summary
cleaning_plan
```

The saved analyses list supports optional filtering:

```text
GET /dataset/{dataset_id}/saved-analyses?analysis_type=cleaning_plan
```

This allows frontend panels to load only relevant saved configs.

---

## 7. Dataset Change Sync

A frontend event is dispatched when the cleaning plan applies an action:

```text
dataset-changed
```

Detail:

```json
{
  "dataset_id": "...",
  "source": "cleaning_plan_apply"
}
```

Panels listening for this event show stale warnings:

- Dataset Intelligence Panel
- Quality Summary Card
- Cleaning Plan Card

This prevents users from trusting outdated deterministic outputs after data changes.

## 8. Support and Debugging

Backend errors can include request IDs through the frontend `errorDetail()` helper.

When a user reports an issue, support should collect:

- dataset ID
- action attempted
- timestamp
- error message
- request ID if visible
- browser console errors
- whether the dataset was modified
- whether undo was attempted

For deterministic intelligence issues, also collect:

- which endpoint failed
- whether combined intelligence failed
- whether fallback individual endpoints failed
- exported JSON/Markdown if available

## 10. Design Notes

The deterministic layer was added as an enhancement, not a replacement.

Existing features remain:

- AI Cleaning Advisor
- AI Insight
- AI SQL Query
- Python Analysis
- Chat With Your Data
- Forecast
- Anomaly Detection
- Root Cause Analysis
- Time Series Explorer
- Pivot
- Correlation
- Compare Datasets
- Share Links
- Scheduled Exports
- Reports
- Branding
- Account management

The deterministic layer provides:

- safer baseline quality signals
- zero-quota analytics
- better report fallback
- clearer cleaning governance
- better support/debug exports
